# Working notes

Read this, then `PLAN.md`. Everything below is the working agreement; `PLAN.md` is the design.

## What this is

A client-only TypeScript web app that characterises finished soybean near-isogenic lines against their recurrent and donor parents from SNP genotype files. Genotype data is parsed and analysed in a Web Worker and never leaves the browser tab. The same pure compute core runs from the command line through `src/cli.ts`.

Open a session **inside this repo**, never in the parent directory. The two siblings, `progeny-selector` (Python) and `field-capture-android` (Gradle), have their own toolchains and their own `PLAN.md`.

## Gates: all of these must pass before every commit

```
npm run lint          # eslint + prettier --check
npm run typecheck     # tsc --noEmit
npm test              # vitest, node project only
npm run test:browser  # vitest browser mode, Chromium and Firefox (docs/adr/0011)
npm run build
```

Plus `npm run fixture` and `npm run contract` followed by `git diff --exit-code -- tests/fixtures contract`: the generators are deterministic and CI fails if a regenerated file differs from the committed one.

Per milestone, not per commit: `npm run test:bench`, the 50K x 200 load in both browsers. Record its printed wall-clock and memory figures in the milestone's verification block and compare them with the previous ones.

## Rules that are not negotiable

- **Never commit real genotype data.** The fixture under `tests/fixtures/synthetic/` is generated by `scripts/make-fixture.mjs`. Edit the generator, never the generated files, and keep that directory under 200 KB.
- **The input contract is shared.** `contract/data-contract.md` (chromosome names, genotype files, `samples.csv`, `markers.csv`, class codes) is mirrored byte for byte into `progeny-selector`, with its cases under `contract/cases/` generated by `scripts/make-contract.mjs`; `docs/data-formats.md` keeps the parameters and outputs. Ask the user before changing any documented column, token, parameter name or output format, and say which sibling file is affected. Any change under `contract/` bumps `contract/VERSION` (major for a changed or removed column, token or rule, minor for an additive optional one, patch for wording; docs/adr/0013), and `node scripts/check-contract-mirror.mjs ../progeny-selector` must then pass.
- **No AI attribution in commits or pull requests.** No `Co-Authored-By`, no generated-with footer.
- **Decisions go in `docs/adr/`** as MADR records. `0014` is the most recent. `0009` carries dated amendments at its end for three decisions taken during M2.5. If you find a recorded decision is wrong, say so and stop rather than quietly working around it.
- Conventional Commits; user-visible changes get a `CHANGELOG.md` entry under `[Unreleased]`.

## How the work is done

Milestone by milestone from `PLAN.md`. For each milestone: state the acceptance criteria you are targeting, implement, make the tests pass, commit.

Self-contained modules are delegated to subagents with a written spec naming inputs, outputs, edge cases and the test that must pass. The main session holds the architecture, the data contracts and the review. Before every commit an adversarial reviewer attacks the genetics (parent-of-origin edge cases, missing data, heterozygotes, uninformative markers), the contract validation and the test coverage; it does not write code. Report what it found and what changed.

Expectations for the fixture are computed by a **second, independent implementation inside `scripts/make-fixture.mjs`**, so a fixture test compares two implementations rather than a function against itself. Preserve that when adding a metric. Note that independence of code is not independence of interpretation: if both implementations share a reading of the rule, a fixture test cannot catch it, so hand-built cases carry that weight.

## Environment gotchas

- `core.autocrlf` is `true` on the maintainer's machine. `.gitattributes` pins the repo to LF; without it a regenerated fixture differs from the committed one and CI fails.
- `python` is Python 2 here; use `python3`.
- Node 24 locally, Node 22 in CI.
- Browser-mode tests need the Playwright browsers once per machine: `npx playwright install chromium firefox`. They go to the user cache, never into the repository. On the maintainer's machine the default cache (`%LOCALAPPDATA%\ms-playwright`) cannot launch browsers (a Windows side-by-side configuration error on byte-identical binaries, cause unknown), so the user environment variable `PLAYWRIGHT_BROWSERS_PATH` points at `%USERPROFILE%\.cache\ms-playwright`; a shell opened before 2026-09-12 must be restarted to see it. Run locally, the tests open headed windows; CI runs them headless.
- The Pages deploy job is gated on a repository variable `ENABLE_PAGES`. `actions/deploy-pages` returns 404 and fails rather than skipping when Pages is off, which marked every push to main as failed. Set the variable to `true` once Pages is enabled with the GitHub Actions source.

## Layout

`src/core/` is pure functions over typed arrays: no DOM, no filesystem, no fetch. `src/io/` parses and validates at the boundary; everything downstream trusts `Dataset`. `src/workers/` is message plumbing only. `src/ui/` displays worker results and computes nothing; `src/ui/tokens.css` holds every colour and dimension, and a component file may contain neither (eslint enforces it). `src/export/` serialises.

Two boundary rules learned the hard way in M2: the worker owns the genotype matrix and never sends it back (ADR 0001), so an exporter that names markers must run **inside** the worker; and a presentation function should take the few facts it needs rather than a whole `Dataset`, or a caller will synthesise a fake one. Each module's header comment states its responsibility and interface. Keep it current.
